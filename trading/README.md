# jptrader — 日本株ペーパートレード・ボット

日本株を対象にした**ペーパートレード（仮想売買）**システムです。
外部ライブラリ不要（Python 3.8+ の標準ライブラリのみ）で動作します。

> **免責事項（重要）**
> - 本システムは教育・検証目的のペーパートレード専用です。実際の発注機能はありません。
> - 出力は投資助言ではありません。実際の投資判断は自己責任で行ってください。
> - バックテストの成績は将来の運用成績を保証しません（過剰最適化・生存者バイアス・
>   スリッページの過小評価などのリスクが常にあります）。

## 全体像

```
trading/
├── run.py                 # CLI エントリポイント
├── jptrader/
│   ├── universe.py        # 売買対象（東証プライム主要30銘柄）
│   ├── data.py            # 日足取得（stooq / Yahoo）・キャッシュ・合成データ
│   ├── indicators.py      # SMA / EMA / RSI / ATR
│   ├── strategy.py        # 戦略（MAクロス順張り・RSI逆張り）
│   ├── backtest.py        # バックテストエンジン＋評価指標
│   ├── portfolio.py       # ペーパートレード口座（JSON 永続化）
│   ├── report.py          # レポート整形
│   └── cli.py             # コマンド定義
├── tests/                 # ユニットテスト（オフラインで完結）
├── data/                  # 価格キャッシュ（git 管理外）
└── state/                 # 口座状態 JSON（git 管理外）
```

## 使い方

```bash
# 対象銘柄の確認
python3 trading/run.py universe

# 日足データの取得（要ネット接続。stooq → Yahoo の順に試行）
python3 trading/run.py fetch

# バックテスト（直近データ全期間）
python3 trading/run.py backtest --strategy ma_cross
python3 trading/run.py backtest --strategy rsi --start 2021-01-01
python3 trading/run.py backtest --strategy ma_cross --param fast=10 --param slow=50

# ペーパートレードの日次実行（1日1回。市場引け後を推奨）
python3 trading/run.py fetch --refresh && python3 trading/run.py trade

# 口座レポート
python3 trading/run.py report
```

ネット接続がない環境では `--offline` を付けると決定論的な合成データで
エンジンの動作検証ができます（**運用判断には使わないこと**）。

```bash
python3 trading/run.py backtest --offline
```

## 組み込んだトレード知識

### 日本株固有の制度

- **単元株制度**: 売買は 100 株単位に切り捨て
- **ティッカー**: 4桁証券コード（stooq は `7203.jp`、Yahoo は `7203.T`）
- **ユニバース**: 流動性の低い銘柄はスリッページが読めないため、
  東証プライムの大型・高流動性銘柄 30 種に限定

### 執行モデル（ルックアヘッドバイアス防止）

- シグナル判定は「その日の引け時点で確定した情報」のみを使用
- 執行は**翌営業日の寄付**（バックテスト）／直近終値（ペーパートレード）
- 片道スリッページ 0.1% ＋ 手数料 0.05% を控除（ネット証券の実勢より保守的）

### リスク管理（戦略より重要）

| ルール | デフォルト | 意図 |
| --- | --- | --- |
| 1トレードのリスク上限 | 総資産の 1% | 連敗しても再起可能な損失に限定（2%ルールの保守版） |
| ポジションサイズ | リスク許容額 ÷ (ATR×2.5) | ボラティリティが高い銘柄ほど小さく張る |
| ストップロス | エントリー価格 − ATR×2.5 | 「損切りできない」を機械的に排除 |
| トレーリングストップ | 終値 − ATR×2.5 に自動引き上げ | 利を伸ばし、含み益の吐き出しを限定 |
| 同時保有数 | 最大 8 銘柄 | 分散と管理可能性の両立 |
| 1銘柄の上限 | 総資産の 20% | 個別銘柄イベント（決算・不祥事）の影響を限定 |

### 戦略

**1. `ma_cross` — 移動平均クロス順張り（デフォルト）**

- 買い: 25日SMAが75日SMAを上抜け、**かつ** 終値が200日SMAより上
- 売り: 25日SMAが75日SMAを下抜け（＋ストップロス）
- 根拠: トレンドフォローは日本株でも古典的に機能が報告されている手法。
  200日線フィルタで下落トレンド中のダマシ（弱い反発でのクロス）を除外する。
  勝率は低め（3〜4割）でも、損小利大＋トレーリングで期待値を作る設計。

**2. `rsi` — RSI 逆張り（押し目買い）**

- 買い: RSI(14) < 30、**かつ** 終値が200日SMAより上
- 売り: RSI(14) > 60（平均回帰の完了）
- 根拠: 長期上昇トレンド銘柄の短期的な売られすぎは平均回帰しやすい。
  トレンドフィルタなしの逆張りは「落ちるナイフ」を掴むため、200日線
  フィルタを必須にしている。

### 評価指標

バックテストは累積/年率リターンに加えて、**最大ドローダウン**（精神的に
耐えられるか）、**シャープレシオ**（リスクあたりの効率）、**勝率と
プロフィットファクター**（期待値の構造）を必ず併記します。リターンの
数字だけで戦略を選ばないこと。

## 日次運用フロー（推奨）

1. 大引け後（15:30 以降）に `fetch --refresh` で最新日足を取得
2. `trade` を実行 → その日のシグナルに基づき仮想約定、状態を保存
3. `report` で資産推移・保有・逆指値を確認
4. 同じ日付での二重実行は自動でスキップされる（`last_run` チェック）

cron 等での自動化例（平日 16:00 JST）:

```cron
0 16 * * 1-5 cd /path/to/sasahin && python3 trading/run.py fetch --refresh && python3 trading/run.py trade >> trading/state/daily.log 2>&1
```

## 制約・既知の限界

- **実発注はしない**。実運用に進む場合は証券会社の API（例: kabuステーション、
  立花証券 e支店 API 等）との接続と、別途の審査・契約が必要
- 値幅制限（ストップ高/安）・特別気配・出来高不足による約定不能はモデル化していない
- 配当・株式分割はデータソースの調整値に依存（stooq は分割調整済み）
- 本リポジトリの実行環境によっては金融データサイトへの接続が
  ネットワークポリシーで遮断されている場合がある。その場合はローカル PC で
  `fetch` を実行するか、環境のネットワーク設定を変更すること
